# ADR-0006: Host-to-Brand резолвинг с единообразным 404 (anti-oracle)

## Status
Accepted

## Context
ADR-0005 описал модель, в которой `GET /share/:hash` сначала ищет поездку по хэшу, затем сравнивает `Host` с `brand.shareDomain` и при несовпадении возвращает HTTP 421 с `{redirectTo: "https://<shareDomain>/s/<hash>"}`. Клиент должен был выполнить `window.location.replace(redirectTo)`.

При реализации выяснилось, что эта схема создаёт несколько проблем:

1. **Oracle-утечка**: ответ с 421 и корректным `redirectTo` раскрывает факт существования бренда и его `shareDomain` любому запросившему — достаточно отправить произвольный хэш на любой домен.
2. **Неверная последовательность join'а**: для формирования `redirectTo` нужно сначала найти поездку (и знать `brand.shareDomain`), что требует либо cross-tenant запроса, либо раскрытия brand-информации до проверки Host. Оба варианта нарушают tenant-границы.
3. **Лишняя логика на клиенте**: обработка 421 в React-компоненте хрупка (JavaScript-disabled browsers, промежуточные прокси, etc.).
4. **Кадди уже валидирует домен** перед выпуском TLS-сертификата через `/internal/validate-domain` — если запрос дошёл до API с несуществующим `Host`, Caddy не выпустит сертификат, а значит в проде такой запрос маловероятен.

## Decision

`GET /share/:hash` (реализован в `apps/api/src/routes/share.ts:12-84`) использует следующую последовательность:

1. Извлечь `Host` заголовок, снять порт, привести к нижнему регистру (строка 17).
2. Если `Host` отсутствует — вернуть `404 {error: "trip not found"}` (строки 18–20).
3. Найти Brand через прямой запрос к таблице `brands`: `lower(brands.share_domain) = host` с использованием индекса `brands_share_domain_lower_idx` из миграции 0011 (строки 24–33).
4. Если Brand не найден — вернуть `404 {error: "trip not found"}` (строки 37–39). Тело идентично случаю «хэш не найден» — намеренно (см. ниже).
5. Выполнить tenant-scoped поиск поездки: `tenantDb(brand).trips.byShareHash(hash)` (строка 42). Если не найдено — `404 {error: "trip not found"}` (строки 43–45).
6. Если `routeGeometry` или `timeline` отсутствуют — `409 {error: "trip not generated"}` (строки 47–49).
7. Успех — `200 ShareResponse` (строки 73–84).

**Ключевое свойство**: ответы на «неизвестный Host» и «неизвестный хэш» идентичны (`404 {error: "trip not found"}`). Это намеренное anti-oracle поведение: внешний наблюдатель не может определить, существует ли бренд с таким доменом или хэш для данного бренда. Никакой `redirectTo` не возвращается никогда.

## Alternatives Considered

- **Оригинальная схема из ADR-0005 (421 + redirectTo)**: отклонена по причинам, описанным в разделе Context. Главное: ответ с 421 и корректным `redirectTo` является oracle — раскрывает `shareDomain` бренда. Кроме того, для построения `redirectTo` сервер вынужден делать cross-tenant поиск по хэшу, нарушая tenant-изоляцию.
- **302 Redirect с сервера**: отклонён ещё в ADR-0005 — сервер не знает протокол клиента; добавляет сложность без выгоды, особенно при on-demand TLS.
- **Host-резолвинг с 403 на несовпадение**: 403 раскрывает факт существования хэша или бренда. Единообразный 404 строже.
- **Middleware-уровень резолвинга**: вынести host→brand в Hono middleware. Отклонено: `/share/:hash` — единственный публичный эндпоинт с brand-резолвингом по Host; вынесение в middleware усложняет тестирование без выгоды.

## Consequences

**Положительные:**
- Нет oracle-утечки: ни факт существования бренда, ни факт существования хэша не раскрываются некорректным запрашивающим.
- Строгая tenant-изоляция: `tenantDb(brand)` гарантирует, что хэш ищется только внутри конкретного бренда; коллизия хэшей между брендами разрешается в `undefined`.
- Нет специальной клиентской логики для 421: клиент обрабатывает только 200, 404, 409.
- Кодовая база проще: удалена ветка 421-redirect и связанный `RedirectResponse` из OpenAPI-схемы.

**Отрицательные:**
- Пользователь, открывший share-ссылку через неправильный домен (например, через кэшированную старую ссылку), получит «Trip not found» без подсказки куда перейти. На практике это маловероятно: Caddy выдаёт TLS только для зарегистрированных доменов.
- Клиентский компонент `apps/web/src/routes/s.$hash.tsx` содержит мёртвую ветку `if (res.status === 421)` (строки 22–29), унаследованную от ADR-0005. Подлежит удалению в отдельном коммите.

## Trade-offs
Строгая anti-oracle изоляция и простота серверного кода важнее удобства крайне редкого сценария «неправильный Host». Caddy-уровневая валидация доменов (`/internal/validate-domain`) делает вероятность этого сценария в проде исчезающе малой.
