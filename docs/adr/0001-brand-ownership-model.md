# Brand Ownership Model

Каждый Brand принадлежит ровно одному Dispatch Manager'у через `brands.owner_id → users.id`. Выбрана простая модель единственного владельца вместо membership-таблицы (`brand_members`) — совместного доступа нескольких DM к одному бренду не требуется, а регистрация пользователей ручная, что снимает необходимость гранулярного ACL.

## Considered Options

- **`brand_members` (многие ко многим)** — отклонено: нет сценария совместного доступа, усложняет ACL без пользы.
- **`CASCADE` при удалении DM** — отклонено: удаление DM уничтожило бы все его Brand'ы, Cargo и Trip'ы. Выбран `RESTRICT` — база блокирует удаление DM, пока у него есть Brand'ы.
- **Передача бренда через API** — отклонено: редкая операция, достаточно ручного `UPDATE` в БД.

## Consequences

- Чужой Brand возвращает 404 (не 403) — не раскрывает факт существования чужого slug'а.
- Миграция существующих данных: колонка добавляется nullable, данные заполняются вручную, затем ставится `NOT NULL`.
- Brand deletion через API — отдельная задача поверх этой модели.
